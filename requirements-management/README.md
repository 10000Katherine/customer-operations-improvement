# Requirements management with Jira and Confluence

This extension turns the operational analysis and DMAIC proposal into a structured BA requirements backlog. The work was completed as guided practice in a personal Jira and Confluence workspace, using synthetic customer support data.

| Deliverable | Purpose |
|---|---|
| [Business Requirements Document v1.0](Business_Requirements_v1.0.md) | Scope, objectives, roles, functional and non-functional requirements, rules |
| [Jira backlog and acceptance criteria](User_Stories.md) | Three epics, six stories and example subtasks |
| [Requirements traceability matrix](Traceability_Matrix.md) | Business objective → Epic → Requirement → Story → proposed verification |
| [Workflow and JQL](Jira_Workflow_and_JQL.md) | Task states, dependency links and saved-query examples |
| [Change management exercises](Change_Management.md) | Proposed threshold changes, impact analysis and approval plan |

## Scope of evidence

- The original BRD was published in Confluence as a draft pending validation, with six Jira Smart Links.
- Jira contains 12 work items. Workflow states are simulated; functionality and UAT have not been delivered.
- The BRD v1.0 retains the assumed 48h warning, 60h escalation and 72h resolution SLA.
- Changes to warning and escalation thresholds were impact-analysis exercises only.
- The original PDF export and genuine interface captures are in a separate evidence package for manual upload. This Markdown module is readable without access to the private Atlassian workspace.

Next stage: BPMN process modelling, followed by UAT and requirements validation.
